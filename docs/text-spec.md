# 文字模块规格

## 当前功能

extract_text_units(doc) 从解析结果中提取正文单元。

输入必须是解析器返回的 rmd_document 对象。

输出保留 type 为 text、status 为 ok 的全部行，
并保留原文、位置及上下文字段。

没有正文时，返回保留列结构的零行数据框。
输入类型不符合要求时，明确报错。

## 当前范围

已完成正文提取、基础空白规范化、文档级字符位置映射、
字符片段生成、整体Jaccard相似度、相同片段定位、
连续精确匹配合并、候选窗口筛选、近似局部对齐及双向覆盖统计。

已支持有限的Markdown排版规范化。尚未实现公式/代码相似度及最终判定。
文字参数和检测性能尚未标定，保留测试集尚未使用。

## 文字规范化

normalize_text(text) 接收单个非缺失字符串，返回：

- text：去除支持的空白字符后的文字。
- source_positions：每个输出字符在输入字符串中的1基字符位置。

支持普通空格、制表符、换行、回车、换页、垂直制表符、
不换行空格及全角空格。

保留大小写、标点及其他字符。
空字符串或全空白输入返回空字符串和空整数位置向量。
非字符、缺失值及多个字符串输入会报错。

normalize_text的位置相对于输入字符串；prepare_text_units负责转换为文档位置。
Markdown处理仅在prepare_text_units中进行，normalize_text仍只去空白。

## 文档级文字准备

prepare_text_units(doc) 提取并规范化正文单元。

输出保留原单元字段，并增加：
- normalized_text：规范化后的文字。
- source_positions：每个规范化字符在 doc$source 中的1基字符位置。

换算使用内容起点 content_start，而非原文单元起点。
各单元分别保留，不跨公式或代码拼接。
没有正文时返回保留列结构的零行数据框。

位置对应解析器统一换行后的 source，不是磁盘字节位置。

## 连续字符片段

make_character_ngrams(text, k = 5L) 按字符生成连续片段，
相邻片段起点相差1。

返回数据框：
- gram：片段文字。
- start：片段在输入字符串中的1基起点。
- end：片段在输入字符串中的1基终点，包含该字符。

输入短于k时返回列结构一致的零行数据框。
重复片段保留各自的位置。
k必须为可表示的正整数。

本函数不自动规范化文本；调用方应传入规范化后的字符串。
默认k仅为初始设置，尚未验证其检测效果。

## 文档级片段生成

make_document_ngrams(doc, k = 5L) 对每个正文单元分别生成片段。

返回字段：
- file_id、unit_id、context_id：文件、单元及上下文标识。
- gram：片段文字。
- normalized_start、normalized_end：在本单元规范化文字中的位置。
- source_positions：片段各字符在 doc$source 中的位置。

不跨正文单元生成片段，保留重复片段的不同出现位置。
无正文或全部单元过短时，返回列结构一致的零行数据框。
即使没有正文，也验证k是否合法。

source_positions可能不连续。
后续计算覆盖率应使用实际字符位置，不能将间隔全部计入。

## 正文Jaccard相似度

compare_text_jaccard(doc_a, doc_b, k = 5L)
比较两份文档已提取正文的不重复字符片段集合。

similarity为交集大小除以并集大小。
同时返回两侧集合大小、交集大小、并集大小和k。

两侧集合均非空时，status为ok。
任意一侧无法生成片段时，similarity为NA，
status为insufficient_ngrams。

本指标不考虑片段重复次数或整体顺序。
仅比较已成功提取的正文，不代表全部文档内容均被分析。
相似度不解释为抄袭概率，也不直接用于最终抄袭判定。

## 相同字符片段定位

match_text_ngrams(doc_a, doc_b, k = 5L, max_pairs = 50000L)
按gram完全相等连接两份文档的片段表。

返回两侧文件、单元、上下文、规范化位置和原文字符位置；
两侧同名字段分别添加_a、_b后缀。

重复片段保留所有出现位置组合。
无匹配时返回列结构一致的零行数据框。

匹配对超过max_pairs时明确报错，不静默截断。
该上限用于控制运行规模，不是判定阈值。

结果仅为短片段候选匹配，尚未合并为较长匹配，
也不直接触发抄袭判定。


## 连续精确匹配与覆盖率

加载顺序：R/parser.R、R/text.R、R/text-matches.R。

merge_exact_text_matches(doc_a, doc_b, k=5L, min_chars=30L, max_pairs=50000L)
将同一单元对、同一位置偏移的重叠或紧邻种子合并为连续匹配。
不跨单元、错配字符或不同偏移合并；这里的精确指去除支持的空白和排版标记后的精确相同，不支持近义改写、插删对齐。
min_chars过滤的是合并后的规范化长度，默认30仅为未标定的起始参数。
保留重复文字的不同对齐，不声称匹配一定来自复制。

输出含规范化匹配文字、长度、两侧单元位置、原文字符向量及行号。
顺序为长度降序，再按两侧单元与位置排列。空表保留相同列结构。
字符向量是匹配字符，行号只是展示范围，不可把整个行范围视为匹配。

summarize_text_coverage(doc_a, doc_b, blocks) 按两侧实际原文字符位置分别取并集：
coverage = 匹配字符并集大小 / 已提取正文规范化保留字符并集大小。
重叠种子、重复对齐只计一次，不填补被去掉的空白；分母包括短于k的正文单元。
无可比较正文的一侧返回NA；有正文但没有达标精确匹配时返回0。
0仅表示当前参数下未覆盖，可能是文字太短或改写，不是无抄袭结论。

analyze_text_pair组合Jaccard、精确匹配、覆盖率及两份解析诊断。
status=insufficient_ngrams表示任一侧没有字符片段；
有片段但解析有warning时为limited；否则为ok。
ok仅表示本次文字分析流程可运行，不代表文档全部被分析或已通过抄袭审查。
status不包含最终抄袭判定。

max_pairs上限继续生效，超过上限明确报错，不能将失败报告成零匹配。

## 快速复现

从仓库根目录执行：
`Rscript examples/run-text-demo.R`

默认自建例子使用k=2、min_chars=2：Jaccard=0.2，

## 近似局部对齐

新增R/text-approx.R，加载顺序为parser.R → text.R → text-matches.R → text-approx.R。
原analyze_text_pair的精确行为不变；新增analyze_text_pair_approx组合精确与近似结果。

流程：
1. 正文规范化单元内切窗口，默认200字符，步长为窗口长度的一半（向下取整，最小1），尾部补齐。
2. 每窗口提取不重复字符种子，默认seed_k=3；至少共享1个种子的窗口对进入候选。
3. 每候选运行局部动态规划：相同+2、替换-1、单侧空位-2，得分低于0时重启。
4. 每窗口对只取一个最高得分对齐。正分并列按扫描时最先出现者；单元格并列依次重启、对角、消耗A、消耗B。
5. 以相同字符数>=min_chars且similarity>=min_similarity过滤；默认30和0.8均未标定。

similarity = 相同字符数 / 对齐列数；替换和插删空位都占分母。
这不是Jaccard，也不是抄袭概率。
输出包括两侧片段、对齐显示、相同字符数、相似度、行号及操作序列。

source_positions_a/b只包含equal操作对应的源字符，用于覆盖率。
aligned_positions_a/b记录所有对齐列的源位置，空位是NA；operations区分equal、replace、consume_a、consume_b。
对齐显示用“-”表示空位；原文自身也可能含“-”，因此判断空位必须看操作序列和NA，不能解析显示字符串。
精确和近似证据合并后按源字符并集计覆盖；替换、插删、空白不计覆盖。
exact_coverage保留精确匹配的覆盖；coverage为两种证据合并后的覆盖。

不同重叠窗口产生完全相同的等值字符映射时去重，其他可能重叠的对齐保留；覆盖统计再次按字符位置去重。

## 近似算法的运行上限与边界

默认每侧max_windows=2000、max_candidates=500、max_seed_pairs=100000、
每对max_cells=250000、总max_total_cells=5000000。超过任何上限明确报错，不静默截断或报告无匹配。
精确分支仍受max_pairs约束。所有上限均为资源管理参数，不是判定阈值。

无共享种子时不运行对齐，所以密集改写、短片段可能漏检。
窗口边界会限制可见范围；一对窗口仅取一个最佳对齐，不能保证枚举全部局部复制。
本算法检测文字层面的少量替换插删，不识别同义改写、数学等价或代码语义。
窗口不跨公式、代码或正文单元。支持的Markdown排版标记在正文准备阶段移除。
候选数、总对齐格数及参数随分析结果返回；解析诊断继续保留。
无有效字符片段标insufficient_ngrams；解析有warning标limited；ok仅表示本次受限文字分析完成。
不能将零覆盖直接当作无抄袭。

## Markdown排版规范化

prepare_text_units在原文位置上标记要忽略的排版字符，然后去除空白。
支持成对的1至3个星号/下划线强调标记、两个波浪号删除线、行首引用和列表前缀、ASCII标点前的转义反斜线。
列表前缀包括-、+、*、最多9位数字后接点或右括号，均需后接空白；允许最多3个前导空格。
只在同一段落上下文内配对；公式、行内代码和代码块里的字符不作为排版标记。
变量名中的内部下划线、未配对标记和不支持的连续标记保留。
raw、content及doc$source不修改；source_positions只指向实际保留字符，不计被忽略标记。
这是保守语法子集，并非完整CommonMark/Pandoc实现。复杂混合强调、表格、Setext标题等不保证规范化。
`Rscript tests/test-text-markdown.R`验证排版与原文映射；`Rscript examples/run-text-markdown-demo.R`演示格式不同但正文一致的比较。
