# 正文语义改写检测方案

状态为已选定技术路线，等待实现和验证。第一版作为可选的人工复核功能交付。

## 1. 目标与边界

在已知两份 Rmd 的前提下，找出措辞或句序改变后仍表达相同主张的正文片段，优先补充现有字符匹配漏掉的段落。报告给出两侧原文和位置，供教师核查来源与上下文。

首版继续使用现有的公式与 R 代码比较、字节一致性、证据覆盖率和 `development-v1` 试判。语义候选单独展示，只用于复核。作业内容和模型推理留在本机。

实现时以已合入分支的接口为准。远端基础版本已有 CSV 排除，参考文件上传和 EXE 启动器随各自的变更评审。语义原型可以先用 CSV 接口验证，等上传和启动器合入后再验证完整交互路径。

## 2. 模型与算法

采用 **E5 初筛＋双向自然语言推断（NLI）核查**。E5 以较低计算成本找出可能对应的段落。NLI 把两个片段联合编码，帮助区分主张一致、单向包含和可能矛盾。模型任务与实际作业复用检测不同，模型选择以项目保留集结果为准。

| 阶段 | 模型与处理 |
|---|---|
| 候选召回 | `intfloat/multilingual-e5-small`。两侧都加 `query: ` 前缀，按注意力掩码做平均池化，再做 L2 归一化。用归一化向量的点积计算余弦分数。 |
| 配对核查 | `MoritzLaurer/mDeBERTa-v3-base-mnli-xnli`。分别输入 A 作为前提、B 作为假设，以及交换顺序的输入，保存两侧的蕴含、中立和矛盾分数。标签映射以固定版本的模型配置为准。 |
| 展示与排序 | 按标定规则分为「主张接近」「可能包含部分共同信息」「存在差异需核查」。在同一类别内，先按双向较低的蕴含分数，再按余弦分数和原文位置稳定排序。 |

### 2.1 正文输入

1. 在现有公共参考或 CSV 排除完成后，读取当前分析视图中的正文单元。保留文档、单元编号、原文字符区间和起止行。
2. 单独生成供模型使用的文本，去掉支持的 Markdown 排版标记，保留词间空格、标点、数字、单位和否定词。公式、代码、标题、已排除单元和无法可靠解析的范围作为边界。单个切片保留原文区间。
3. 优先使用完整段落。超长段落按句切分，预算以分词后的长度为准。每段初始上限为 192 词元，预留前缀、句对分隔和特殊词元。调用前同时核对两种分词器及句对长度。极端长句按可追溯的原文范围拆分，报告标记拆分或跳过情况。

### 2.2 召回与核查

- 计算 A、B 的段落对余弦分数。对每侧每段取 Top-K，并保留 A→B 与 B→A 的并集。原型初始取 `K = 5`，由开发集测量改写片段进入候选池的比例后再调整。互相排名靠前的配对优先，但单向召回的配对仍可保留。
- 对候选对运行双向 NLI。分别记录 `min(蕴含(A→B), 蕴含(B→A))` 与 `max(矛盾(A→B), 矛盾(B→A))`。只有两个方向都达到开发集门槛，且没有明显冲突时，才优先展示为「主张接近」。单向蕴含可保留为「部分对应」，以便发现段落扩写、删节和改写后新增说明。
- 数字、单位、比较方向或常见否定词不同时，展示具体差异并降低默认复核优先级。差异检查只提示原文变化，遇到单位换算、取整或等价表达时由人工判断。
- 如提供公共参考，可将与参考语义接近但未被完整单元规则排除的片段标为「可能涉及公共来源」，显示参考位置并降低默认优先级。自动排除仍采用现有精确规范化规则。未提供参考时，报告保留共同题干和标准解法可能形成匹配的说明。

## 3. 接口、报告与离线部署

| 环节 | 实现约定 |
|---|---|
| R 接入 | 建议在 `analyze_rmd_pair()` 完成解析及排除后调用可选语义模块。入口配置包含是否启用、本地模型目录、段落及候选预算和超时。默认关闭。 |
| 推理进程 | R 通过 UTF-8 JSON 把段落编号和文本交给独立的本地 Python 进程。Python 批量推理后返回模型标识、状态、两侧编号和分数。文件路径、原文定位和排除策略由 R 管理。 |
| 返回校验 | R 验证协议版本、段落编号、分数范围和配对唯一性，再从本地映射得到原文与行号。推理输出始终作为数据处理。 |
| 资源上限 | 原型每侧最多 200 个文本切片，每对作业最多 100 个候选进入双向核查，设 60 秒推理超时。参数为初始资源预算，按目标 Windows 机器实测调整。超限须明确标记并记录实际覆盖范围。 |
| HTML | 新增「语义相似段落」，默认最多展示 5 条。逐项显示 A/B 原文、行号、核查标签和差异。两侧都与现有字符证据位置重叠时，在语义条目中引用对应的字符证据，避免当作两条独立发现。 |
| 交付 | 原型先用锁定版本的 Python 环境验证，再导出 ONNX，并核对同一批样例上的输出与排序。Windows EXE 继续内嵌检测器，语义模型和运行环境作为可选离线组件。清单记录模型版本、分词器、运行库及文件 SHA-256。 |

推理接口区分 `disabled`、`ok`、`limited` 和 `error`。已启用但模型缺失、超时、崩溃或返回格式错误时，报告说明语义检测未完成，其他模块继续输出。检测期间只读取本地模型，不自动下载依赖或向外部服务发送正文。推理过程和常规日志只保留运行状态、数量及版本，原文不进入常规日志。

## 4. 数据、评测和启用条件

### 4.1 样本与标注

沿用现有的开发集与保留集隔离方式，新增两侧原文区间和关系标签。至少覆盖以下类型：

- 有来源记录的改写，包括同义替换、句序变化、段落拆分和新增解释。
- 未接触源答案的真人同题独立作答，包括使用相同统计术语或标准解法的答案。
- 原始题干、空白模板及其改写版本。
- 数字、单位、否定、变化方向或实验组别改变的例子。

标签区分「有复用来源」「同题独立」「公共内容」「有实质差异」和「不确定」。两位标注者独立复核有争议的样例，记录仲裁理由。人造改写用于开发与回归，单独报告。划分按题目或源作业进行，同一源的改写变体不得跨组。私有作答留在本地忽略目录。

### 4.2 对照实验与验收

在相同的输入、公共排除规则、人工复核条数和保留集上比较现有字符算法、字符算法＋E5、字符算法＋E5＋双向 NLI。

| 指标 | 口径 |
|---|---|
| 候选召回率 | 已标注的改写片段对中，进入 E5 候选池的比例。用于区分召回不足与 NLI 误过滤。 |
| 展示定位召回率 | 在固定复核条数内，找回的真实改写片段对占比。两侧区间均须命中。 |
| 独立作答误提示 | 每对同题独立作答中错误展示的改写提示条数，同时报告出现至少一条误提示的作业对比例。 |
| 边界与耗时 | 记录重复定位、反义误提示、语义检测未完成比例、冷启动和热运行耗时。 |

定位评估按 A、B 两侧原文字符区间计算交并比，原型以两侧各达到 0.5 为初始命中条件，每个标注片段对只匹配一次。开发集确定展示条数、门槛、允许的误提示上限及运行预算，并冻结这些口径。保留集统一报告样本数、分项结果和不确定性，按题目或源作业分组计算区间。只有两阶段方案在相同误提示预算下提高定位召回，且达到目标机运行预算，才推荐启用。若双向核查损失过多真实改写，保留它的差异提示用途并回到开发集修订。

## 5. 实施顺序

1. **接通原型。** 确定正文切片和双向 NLI 接口。用自建样例核对 UTF-8、行号、边界、同题误提示和失败回退。
2. **接入报告。** 验证断网、缺失模型、进程超时和中文路径。确认关闭语义模块时原有证据和试判结果保持一致。
3. **标定与冻结。** 补充独立作答，完成三组对照，记录模型版本、阈值、运行时间和失败率。
4. **保留集验证。** 按冻结口径一次性评价。若后续希望将语义证据纳入试判，另立决策记录并重新验证。
